Crash findings
==============

  fuzzTestFetchConsumer surfaced a reproducible NullPointerException
  in handleFetchRequest within ~16 fuzz iterations:

    java.lang.NullPointerException: Cannot invoke
      "String.getBytes(java.nio.charset.Charset)" because
      "this.topic" is null
      at FetchResponseData$FetchableTopicResponse.addSize(...)
      at FetchResponseData.addSize(...)
      at Message.size(...)
      at FetchResponse.sizeOf(...)
      at FullFetchContext.getResponseSize(FetchSession.scala:430)
      at KafkaApis.processResponseCallback$1(KafkaApis.scala:1000)
      at KafkaApis.handleFetchRequest(KafkaApis.scala:1033)

  Trigger:
    1. FetchManager#newContext returns a TopicIdPartition whose topic
       name is null (the conventional encoding for an unresolved topic
       id in a fetch session), AND
    2. The FetchRequest version is <= 12 (versions for which the
       FetchResponse schema still carries the topic name on the wire;
       see FetchableTopicResponse.addSize line 755 of the generated
       FetchResponseData.java).

  A deterministic mock-driven repro is committed as
  core/src/test/scala/unit/kafka/server/KafkaApisHandleFetchRequestNpeReproducerTest.scala
